# Choosing between these and the `AI.*` functions

> **Source:** [`bigquery-ai/reference/cloud-ai-service-models.md#choosing-between-these-and-the-ai-functions`](https://github.com/statmike/bigquery-data-science/blob/main/bigquery-ai/reference/cloud-ai-service-models.md#choosing-between-these-and-the-ai-functions)

Two members now have **zero-DDL Cloud AI counterparts** in the `AI.*` namespace — [`AI.TRANSLATE`](https://github.com/statmike/bigquery-data-science/blob/main/bigquery-ai/reference/managed-functions.md#aitranslate) for Cloud Translation and [`AI.CHUNK_DOCUMENT`](https://github.com/statmike/bigquery-data-science/blob/main/bigquery-ai/reference/document-processing.md#aichunk_document) for Document AI Layout Parser — while every member also has a generative alternative via [`AI.GENERATE`](https://github.com/statmike/bigquery-data-science/blob/main/bigquery-ai/reference/general-purpose-functions.md) over text or an `ObjectRef`. Each notebook runs both over the same rows so the comparison is measured rather than argued. What the comparisons keep showing:

**Reach for [`AI.TRANSLATE`](https://github.com/statmike/bigquery-data-science/blob/main/bigquery-ai/reference/managed-functions.md#aitranslate) or [`AI.CHUNK_DOCUMENT`](https://github.com/statmike/bigquery-data-science/blob/main/bigquery-ai/reference/document-processing.md#aichunk_document) first** when your task is pure translation (especially with per-row target languages) or layout-aware RAG chunking of PDFs/Office/HTML — you get the deterministic Cloud AI service without `CREATE MODEL` DDL. Switch to `ML.TRANSLATE` when you need Cloud resource connection service-account auth, single-region data residency, or `DETECT_LANGUAGE` / `TRANSLITERATE_TEXT`; switch to `ML.PROCESS_DOCUMENT` when you need specialized Document AI processors (Invoice, Expense, Form, OCR on standalone images, Custom).

**Reach for a Cloud AI service model** when the output is a record: a fixed API version, a published per-unit price, a closed vocabulary, connection-based service-account auth, and behavior that does not move when a model default does. When the service cannot do something, it says so — an unsupported language, an unsupported feature, an unreadable file all arrive as errors in a status column.

**Reach for a generative `AI.*` function** when the deliverable is not the service's output: a summary rather than a transcript, your categories rather than the taxonomy's, translate-and-rewrite rather than translate. It will also answer questions the service refuses — and that is the trade, because it answers them the same confident way whether or not it is right, with no status column and no confidence beside the answer. A refusal is information; a fluent guess is not.

**Use both** when the record and the analysis are different artifacts: the service output as the durable, priced, inspectable column, and the generative function over *that column* — where the input is text you can read instead of media you cannot.
